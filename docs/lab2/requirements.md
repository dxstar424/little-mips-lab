# LAB2: 多周期访存

## 实验目标

在完成 LAB1 流水线的基础上：

1. 添加内存访问映射模块 **mmap**，完成对 BaseRAM 和 ExtRAM 的精确管理
2. 实现内存访问控制模块 **MemCtrl**，正确处理内存访问请求
3. 在 MemCtrl 中实现**多周期访存**策略
4. 在 MemCtrl 中实现**写缓冲**策略
5. 可能需要在 core 中添加新端口或新逻辑电路

可使用 headder 中的 `SRAM_TIME` 来控制访存的周期数。

---

## 为何需要多周期访存

在流水线处理器中，时钟周期的长短由各流水级中**最长一级的时延**限制。
在经典 5 级流水线中，**存储器访问的时延远高于寄存器计算**，这限制了处理器频率。
通过将内存读写由 1 周期更改为多周期，并在 MEM 阶段引入暂停操作，可以显著提高处理器频率。

---

## 内存访问模型

### Lab1 模型

CpuCore 直接与 RAM 连接。

### Lab2 模型

- BaseRAM 和 ExtRAM 是**独立的芯片**，理论上可以并发读写
- 虚拟地址映射：
  - `0x80000000 - 0x803FFFFF` → **BaseRAM**（代码段）
  - `0x80400000 - 0x807FFFFF` → **ExtRAM**（数据段）
- 需要添加 **mmap 模块**将 BaseRAM 和 ExtRAM 的请求统合

### 关于异步 RAM

本次实验使用的 RAM 为**异步 RAM**，无需时钟输入。

### MemCtrl 架构

```
Core ←→ MemCtrl ←→ BaseRAM (代码段)
                 ←→ ExtRAM (数据段)

```

## MemCtrl 设计参考

### 可选端口设置

| 端口组       | 信号                                             |
| ------------ | ------------------------------------------------ |
| 时钟/复位    | clk, rst                                         |
| 指令读请求   | PC, 指令读使能, 指令数据, 指令读暂停信号         |
| 数据读请求   | 读地址, 读使能, 读数据, 数据读暂停信号           |
| 数据写请求   | 写地址, 写使能, 写数据, 数据写暂停信号, 字节掩码 |
| RAM 芯片接口 | 地址, 读写使能, 字节掩码, 片选使能, 读写数据     |

**注意**：RAM 芯片的使能信号为**低有效**（参考 thinpad_top 端口中 RAM 相关部分）。

## 写缓冲策略

当存储器访问需要多个周期时，写缓冲策略是一个常见的优化策略：

对于一次数据写请求，若请求触发时，**没有其他的数据访问请求**，则可以不用暂停 CPU，而是将当前的写请求缓存在寄存器中。这样，数据写和 CPU 运行可以**并行执行**，进一步提高 CPU 效率。

## 报告思考题

> 尽管多周期访存显著提高了流水线频率，但并没有真正提高运行效率，请解释原因？
> （提示：IF 阶段）

**参考答案思路**：因为 IF 阶段仍然需要访问存储器来取指令。即使 MEM 阶段的数据访存变为多周期，IF 阶段每次取指令仍需等待 SRAM 访问周期。所以整体 CPI 不变（甚至因为等待变多），只是时钟频率上限提高了。在有 Cache 之后（Lab3），才能真正利用高频优势。
