# LAB3: Cache

## 实验目标

在完成 LAB2 流水线的基础上：
1. 添加**指令 Cache**（数据 Cache 可选）
2. 修改内存访问控制模块 MemCtrl，正确处理内存访问请求
3. 可能需要在 core 中添加新端口或新逻辑电路
4. Cache 控制逻辑使用**写回**（Write-back）策略
5. Cache 至少容纳 **32 条指令**，至多 **1024 条指令**
6. Cache 可以使用按 Block 排列的**寄存器模拟**，也可以借用**IP 核 BRAM** 完成

---

## Cache 与多周期访存的关系

在 Lab2 中，由于 **IF 阶段仍然需要访问存储器**，多周期访存并没有实质性提高处理器性能。

但引入 Cache 后：
- 对于处理器中多次访问的指令/数据，可以将访存周期**压缩到 1-2 个周期**
- 进而真正提升性能

**在单周期访存模型中，Cache 没有任何作用。**

## 实验提示（需要思考的问题）

### Cache 命中时序
- 方式一：**本周期命中，本周期读取数据**
- 方式二：**本周期命中，下周期读取数据**
- 请选择一种方式实现

### Cache 地址映射
- 应该如何分割存储地址作为 Cache 的**标志（Tag）、组号（Index）、块内偏移（Offset）**？

### Cache 替换与分组
- 替换策略可以随意选择：LRU、直接替换等
- 分组策略需要可以选择 **2、4、8 路组相联**结构

### LB/SB 指令适配
- LB、SB 指令是否需要 Cache 相关适配？（视 core 和 Memctrl 的实现方式）

### Cache 更新冲突
- 如果在更新 Cache 的过程中遇到了新的内存读写请求，应当如何完成适配？
- 数据写是否会影响 Cache（有效位、写回策略）？

### MemCtrl 暂停信号
- Cache 一次更新需要多条指令数据，在更新过程中，Memctrl 的暂停信号应该如何修改？
