# LAB4: 分支预测

## 实验目标

在完成 LAB3（含 iCache）流水线的基础上，添加**动态分支预测器**（1 位或 2 位）。
为了使 CPU 正常运行，可能需要在 core 中添加新端口或新逻辑电路。
分支预测器可以使用按 Block 排列的寄存器模拟，也可以借用 IP 核 BRAM 完成。

---

## 何为分支预测

在经典 5 级流水线中，分支指令在 EX 阶段才知道是否跳转。但 IF 阶段已经取了后续指令。
无分支预测时，流水线只能等待 EX 阶段判定后才知道正确路径，产生**控制冒险**。

MIPS 通过**延迟槽**缓解控制冒险：分支指令后的 1 条指令无论跳转与否都会执行。
但这只能隐藏 1 个周期的损失。引入分支预测器后，CPU 在 IF 阶段就**猜测**分支方向并提前取指，进一步提升性能。

---

## 动态分支预测器设计

### 预测器结构

分支预测器的核心是**分支历史表（Branch History Table, BHT）**：

```
PC ──→ [Index提取] ──→ BHT查找 ──→ 预测结果（跳转/不跳转）
                              └──→ 目标地址（BTB，可选）
```

| 组成部分 | 说明 |
|----------|------|
| Tag | 存储部分 PC 高位，用于识别该 entry 是否匹配当前分支 |
| 预测位 | 1 位或 2 位饱和计数器，记录历史跳转行为 |
| 目标地址 | （可选）记录上次跳转的目标地址，用于 JR/JALR 等间接跳转 |
| Valid | 该 entry 是否有效 |

### 容量要求

推荐记录 **8-256 条分支**。可以通过参数化配置。

### 地址划分

参考 iCache 设计，可将 PC 划分为 Tag/Index：

```
PC[31:n] Tag | PC[n-1:2] Index | PC[1:0] 忽略（指令对齐）
```

具体位宽取决于 BHT 大小。例如 16 条分支 = 4 位 Index。

### 预测策略

- **1 位预测器**：记录上次的跳转结果，直接用上次结果预测下次。弱点：循环边界处连续两次预测失败（进入和退出各一次）。
- **2 位预测器**：使用饱和计数器（00 强不跳/01 弱不跳/10 弱跳/11 强跳），需要连续两次预测失败才改变方向，对循环更友好。

### 替换策略

BHT 满时可使用 Round-Robin 或直接覆盖（与 iCache 类似）。

## 分支指令类型分析

MIPS C1/C2/C3 指令集中的分支指令：

| 类型 | 指令 | 特点 |
|------|------|------|
| 条件分支 | BEQ, BNE, BGEZ, BGTZ, BLEZ, BLTZ | 跳转目标 = PC+4+offset，方向取决于寄存器值 |
| 无条件跳转 | J, JAL | 跳转目标由指令编码确定（imm 字段），**总是跳转** |
| 间接跳转 | JR, JALR | 跳转目标 = 寄存器值，目标地址可能每次都不同 |

---

## 需要处理的边界情况

### 1. Tag 覆盖
BHT 记录的 PC 和当前 PC 的 Index 相同但 Tag 不同——说明是不同分支映射到同一 BHT entry。
此时直接按 Tag 不匹配处理（视为未命中），替换或重新分配该 entry。

### 2. 预测失败
- **预测跳转但实际不跳**：IF 已取了跳转目标地址的指令，需要**冲刷流水线**（flush IF/ID），重新从 PC+4 取指
- **预测不跳但实际跳**：IF 已按顺序取了 PC+4，需要**冲刷流水线**，重新从跳转目标地址取指

### 3. 跳转地址改变（JR/JALR）
JR/JALR 的跳转目标来自寄存器，可能每次执行都不同。
如果 BHT 记录了目标地址，EX 阶段发现实际目标与预测不一致时需要冲刷流水线。
可选的保守策略：对 JR/JALR 不预测（直接 stall）。

### 4. 指令覆盖
原本某 PC 是分支指令，后续该 PC 被覆盖为非分支指令。BHT 中残留的 entry 需要 Invalid。
可以通过 Decode 阶段检测：若 BHT 预测跳转但译码发现当前指令不是分支，则冲刷。

### 5. 延迟槽
MIPS 的延迟槽意味着分支指令后紧跟的 1 条指令**总是执行**，即使预测失败也不能被冲刷。
在流水线冲刷时需要保留延迟槽指令。

## 流水线修改要点

### IF 阶段
- 用 PC 查询 BHT
- 若预测跳转且命中 → 下一 PC = BHT 记录的目标地址
- 若预测不跳或未命中 → 下一 PC = PC+4（顺序）

### EX 阶段（验证）
- 分支指令在 EX 阶段产生实际跳转方向和目标地址
- 与预测结果比较：
  - 预测正确 → 正常流水
  - 预测失败 → 冲刷 IF/ID（保留延迟槽），更新 BHT

### BHT 更新
- EX 阶段分支结果出来后更新对应 entry 的预测位和 Tag
- 对于 JR/JALR，还需更新目标地址

---

## 与 iCache 的交互

Lab3 中 iCache 已插入在 Core 和 MemCtrl 的指令路径之间。
分支预测器在 iCache **之前**的 IF 阶段工作——先预测下一 PC，再经过 iCache 取指。
两者独立运行：iCache 处理取指延迟，分支预测器处理控制冒险。

预测失败时的流水线冲刷会连带 iCache 的取指请求作废，但 iCache 内部状态不需要特殊处理。

## 验证标准

### 正确性
- labf.bin 和 testfile.bin 的 regs 值必须与 Lab1/Lab2/Lab3 完全一致
- 所有 MIPS 语义不变（分支预测对外透明）

### 性能对比（报告用）
- **无分支预测**：每条分支指令至少浪费 1 个延迟槽 + 可能的额外等待
- **有分支预测（命中）**：IF 连续取指，无气泡
- **有分支预测（失败）**：冲刷 IF/ID，额外损失 1-2 周期
- labf 的大循环中，循环分支在第一次迭代后预测稳定，后续迭代的 IF 不再断流
